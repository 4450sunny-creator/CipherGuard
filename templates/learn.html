SECURITY FIELD GUIDE

Understand the tools, not just the buttons.

A plain-language guide to the concepts behind CipherGuard.

01

What is sensitive data?

Sensitive data includes information that could enable account access, expose private details, or compromise systems if disclosed: API tokens, private keys, passwords, personal identifiers, and internal configuration.

If a credential was exposed, rotate or revoke it. Removing it from one file does not invalidate copied credentials or erase every historical copy.
02

What does encryption do?

Encryption transforms readable plaintext into ciphertext using a cryptographic key. CipherGuard uses AES-GCM, an authenticated-encryption mode that protects confidentiality and detects unauthorized changes.

03

Why derive a key from a passphrase?

A human password is not itself a good AES key. Scrypt combines the passphrase with a random salt and deliberately uses computational resources to make password guessing more expensive. A fresh nonce is generated for each encryption.

04

What is an authentication tag?

Authenticated encryption produces a tag. During decryption, the library verifies it before returning plaintext. If the passphrase is wrong or authenticated data has changed, verification fails.

05

What is secret scanning?

A scanner looks for known patterns and likely indicators. It can miss unfamiliar formats and flag harmless text. CipherGuard reports possible matches rather than declaring a file safe or compromised.

06

What should production add?

  • Threat modeling and independent security review
  • CSRF protection, authentication, rate limits, and authorization
  • Safe isolation for uploaded files and strict retention/deletion controls
  • Secure key lifecycle, backups, monitoring, and incident response
  • Automated tests, fuzzing, and dependency management
